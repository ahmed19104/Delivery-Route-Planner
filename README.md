Delivery Route Planner — Technical Challenge 2026A .NET 8 Console Application designed to organize delivery requests into optimized trips based on vehicle weight constraints, urgent priorities, and area grouping.🛠️ FeaturesMulti-Criteria Sorting: Prioritizes urgent items while naturally grouping deliveries heading to the same destination.Capacity Management: Enforces a strict 10.0 kg limit per vehicle trip.Trip Capacity Efficiency Metric (Extension): Calculates and displays the load utilization percentage for each trip:$$\text{Load Utilization (\%)} = \left(\frac{\text{Total Trip Weight}}{10.0\text{ kg}}\right) \times 100$$Helps logistics managers evaluate how efficiently vehicle capacities are utilized across all routes.Input Validation & Filtering: Logs invalid inputs separately without breaking pipeline execution.🚀 How to RunClone or download the repository.Ensure .NET 8 SDK is installed on your machine.Place your sample input file deliveries.json in the project root directory.Run the application using the CLI:Bashdotnet run
🧠 Technical Reflections & Q&A1. Reasoning & Decision MakingThe solution utilizes a Greedy Strategy combined with multi-level sorting:Validation & Filtering: Invalid inputs (e.g., packages exceeding 10 kg, or with zero/negative weights) are filtered out immediately and logged as edge cases.Multi-Criteria Sorting: Valid deliveries are sorted primarily by Priority (ascending, so urgent items are handled first) and secondarily by Area (alphabetically) to group same-destination deliveries naturally.Trip Packing: Iterates through sorted deliveries, filling the current vehicle until adding the next item would breach the 10.0 kg limit, at which point a new trip is instantiated.2. Challenges & Edge CasesTrade-off Balancing: Balancing strict priority constraints with optimal area grouping without breaching the 10.0 kg threshold.Edge-Case Validation: Handling single heavy items exceeding 10.0 kg gracefully without failing the entire execution pipeline.3. Algorithmic Trade-offsBecause this is a Greedy Approach prioritizing urgency over strict bin-packing (a variant of the NP-Hard Bin Packing Problem), it may not always yield the overall optimal grouping:Example: If a Priority 1 package weighs 2 kg (Area A) and another Priority 1 package weighs 7 kg (Area B), they will be grouped in the same trip to honor urgency first—rather than waiting for a lower-priority package from Area A that might fill the remaining space better.4. Scalability (1,000,000+ Requests)BottleneckDescriptionMemory ConstraintsLoading 1,000,000 JSON records into memory as objects creates high RAM overhead.Sorting OverheadIn-memory sorting has an $O(N \log N)$ complexity, creating a processing bottleneck at scale.Solution for Scale:Transition to a database with composite indexes on (Priority, Area).Stream data using IAsyncEnumerable or process in paginated batches.Calculate and process trips incrementally instead of loading the entire dataset into memory.5. Future ImprovementsDynamic Configuration: Move capacity limits and rule definitions to an appsettings.json file.Distance Matrix Integration: Integrate a graph-based route optimization library or external API to calculate exact road distances instead of plain string matching.Unit Testing: Implement comprehensive test coverage using xUnit to handle empty input files, maximum boundary conditions, and priority ties.
